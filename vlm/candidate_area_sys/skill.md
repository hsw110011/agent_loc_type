# Node 3 Skill：道路引导的特殊候选区域搜索

> **Skill ID**：`road_guided_special_region_discovery`  
> **Version**：`1.0`  
> **适用节点**：Node 3 — VLM 特殊候选区域识别  
> **输入图像**：单张道路增强卫星地图（道路分割预测结果已半透明叠加到原图）

## 0. Skill 定位与使用方式

本 Skill 仅定义**如何观察图像、沿道路搜索、形成候选区域及进行复核**，不重新定义角色、业务判断阈值或 JSON 字段。

- **Prompt**：定义任务目标、角色边界与通用约束。
- **Skill（本文）**：指导逐步执行道路引导的候选区域发现。
- **Rule**：提供特殊区域的选择依据、保留条件、合并原则及其他业务规则。
- **Schema**：唯一规定返回内容的字段、取值和 JSON 结构。

按照以下阶段完成图像分析。各阶段是**视觉检查工作流**，无需在最终结果中逐步复述；最终仅按照 Schema 返回候选区域。

## Step 1：理解输入图像与道路增强标注

1. 确认当前输入是**同一张图像**：卫星地图及叠加其上的道路分割预测标注，而不是两张需要自行配准的图。
2. 将彩色道路叠加区域作为**搜索提示**，用于快速定位潜在道路走向和道路分支；其颜色不是卫星地图中真实地物的颜色。
3. 结合未被遮盖的纹理、道路形态、交叉关系及周边地物，检查标注区域是否符合可见道路特征。
4. 对未着色区域独立观察：VLM 根据原图认为是道路或可能可通行的区域，均可进入后续搜索，包括土路、田间便道、场地通道、开阔硬化场地和连续裸露地表；不要求具有正式道路形态。
5. 如果遮挡、阴影、树冠或预测错误导致道路不能确认，在后续分析中保留不确定性。

本文后续的“道路”“路段”“沿路”和“道路关联”均包含上述潜在可通行区域。Mask 和 polygon 只辅助搜索，不限制搜索范围。潜在通行判断必须来自原图中的地表、连续性及障碍线索，并使用“可能”等限定语，不能等同于已验证的车辆通行能力。

**阶段目标**：建立对“道路大致在哪里、标注有哪些不可靠位置”的初步认识，不急于输出 BBox。

## Step 2：建立全局道路搜索顺序

1. 通览全图，识别主要连续道路、次要分支、路口、弯道以及道路可能被遮挡或中断的位置。
2. 为避免随机跳跃式观察，采用固定搜索顺序：
   - 先查看图像中的主要连续道路；
   - 再从上到下、从左到右依次检查其余道路和分支；
   - 对交叉口、环岛、道路汇合处进行单独复查；
   - 对已检查路段不作无意义的重复扫描。
3. 将具有明显环境变化的位置作为**路段分界线索**，例如道路从开阔地进入建筑密集区、道路两侧地物类型发生变化、出现复杂交叉口等。
4. 如存在相互不连通的道路片区，分别进行搜索，不因其中一处特征显著而忽略其他片区。

**阶段目标**：形成可覆盖全图可见道路的搜索次序。这里的道路划分仅用于视觉搜索，不要求输出精确道路中心线或拓扑图。

## Step 3：沿道路逐段扫描周边环境

对当前道路或路段，按相同的观察顺序检查：

1. **路面与道路形态**：观察道路是否开阔、弯曲、交叉、分岔，是否存在明显路面标识或结构变化。
2. **道路两侧近邻环境**：观察建筑物、围墙、植被、空地及其他地物与道路的相对位置。
3. **稍远处的相关环境**：仅在其可能对车辆定位具有空间约束或遮挡意义时，进一步观察道路周围较远的结构。
4. **沿路变化**：比较当前路段与相邻路段是否存在显著差异，寻找环境特征发生变化的边界。
5. **有利特征与退化特征**：同时寻找可能有助于定位的区域，以及可能导致匹配歧义、缺少特征或遮挡的区域。

扫描时始终以**道路及周边定位相关环境**为观察中心，不以建筑物或地形在图中的显眼程度代替道路相关性。

## Step 4：从五个定位视角发现候选线索

在 Step 3 的每段道路上，使用以下五种**观察视角**发现值得进一步分析的位置。这些视角是搜索线索，**不是最终适用性结论**；具体如何判断和筛选，以 Rule 为准。

| 观察视角 | 沿道路重点观察什么 | 初步关注的问题 |
|---|---|---|
| 语义匹配 | 路口形态、道路布局、建筑与地物组合、可辨识的稳定语义地标 | 区域是否具有可区分的语义和空间组合？ |
| 地形/高程匹配 | 建筑屋顶与边缘、投影阴影、坡地、山体及可见地表起伏线索 | 是否可能存在具有辨识度的高程或三维结构？ |
| SLAM | 稳定几何结构的丰富程度、形状多样性、纹理线索、重复布局 | 是否具有潜在观测约束，或可能出现特征稀疏与几何退化？ |
| 里程计递推 | 道路的长距离连续性、急弯、复杂转向及可能存在的特殊路面场景 | 有无值得进一步验证的运动估计风险线索？不得据此推断实际漂移。 |
| GPS/GNSS | 开阔程度、建筑密集程度、树冠覆盖、潜在天空遮挡 | 是否存在相对开阔的环境或潜在遮挡风险？ |

**使用要求**：

- 一处区域可以同时触发多个观察视角；不必为了每一种定位方式都专门生成 ROI。
- GPS/GNSS 与里程计递推的判断尤其依赖实际设备及运行信息；本阶段仅寻找环境线索。
- 不因为某区域对一种方法可能不利，就将其排除：**潜在退化区域同样属于值得记录的特殊区域**。

## Step 5：利用俯视视觉线索进行定性空间推断

在具有潜在三维结构的道路周边，继续做一次空间特征检查：

1. **屋顶与建筑边界**：观察屋顶外形、尺寸差异、边界形态和排列方向，推断可能存在的人工立体结构。
2. **阴影**：结合阴影位置和形态，辅助判断是否存在突出的垂直物体或相对高度变化；同时考虑阴影可能与拍摄光照有关。
3. **遮挡关系**：通过树冠、建筑屋顶、侧立面或道路局部遮挡，理解地物之间的可能空间层次。
4. **地表纹理与地貌**：观察道路附近的坡面、山体纹理、明暗变化和地物分布，判断是否存在潜在地形起伏。
5. **空间独特性与重复性**：观察不同方向的结构组合、重复建筑、长直均质路段等，记录可能有助于区分位置或造成匹配歧义的线索。

对每一项空间推断，区分：

- **可见事实**：图像中可以直接指出的形状、阴影、分布和空间关系。
- **定性推断**：由这些线索推测出的潜在三维结构或定位意义。
- **待验证事项**：需要 DSM、实际传感器观测或专业分析工具才能确认的内容。

无需进行真实深度估计、三维重建或物理量测。

## Step 6：根据 Rule 形成候选 ROI

完成道路扫描后，结合 Rule 将具有明确视觉依据的特殊位置整理成候选区域。

1. 为每个候选位置明确**对应道路或路段**、直接观察到的特征，以及值得保留的原因。
2. 同时允许保留潜在有利区域、潜在退化区域和证据不足但值得进一步确认的区域，具体范围遵循 Rule。
3. 尽量使 ROI 包含**相关道路 + 支撑判断的周边地物**，不能只框住远离道路的显著建筑。
4. 区域范围以完整表达所选特征为准：不无故扩大到整片城区，也不裁掉支持判断的关键地物。
5. bbox 使用四个顺时针顶点，优先采用贴合道路走向的倾斜矩形，也可用凸四边形；必须正面积、不自交、不越界。坐标采用实际输入图像的像素边缘，可使用小数。
6. 如果观察到同一连续路段上多个特征相近的小区域，依据 Rule 考虑合并；如果场景显著不同，应分别保留。
7. 逐对检查实际四边形；任意两个区域内部不能重叠，边界接触允许。存在交叠时缩小、拆分或合并；无法消除时只保留有充分依据的区域，不因不同定位视角重复选区。

**阶段目标**：形成一组相互区别、位置可追溯、描述能够被图像支持的候选区域，而不是尽可能多的框。

## Step 7：反向复核、查漏与去重

在输出之前进行一次**独立于初次扫描顺序的复核**：

1. **道路覆盖复核**：检查主要道路、次要分支、复杂路口和道路场景变化处，是否有明显值得关注但被遗漏的区域。
2. **Mask 偏差复核**：检查是否因没有道路标注或正式道路形态而忽略原图中有视觉依据的潜在通行区域，或仅凭标注误检而选择缺乏视觉依据的位置。
3. **证据一致性复核**：每个候选区域的场景描述、选择理由，是否都能从对应图像位置得到支持。
4. **区域范围复核**：BBox 是否覆盖相关道路和支撑特征，是否明显过大、过小或偏移。
5. **区域互斥复核**：逐对确认实际四边形内部均不重叠，包括包含、重复及部分交叠；倾斜区域的水平外接框相交不等于真实区域相交。
6. **不确定性复核**：对于阴影、地形高差、车载可观测性等推断，是否把不确定推断误写成确定事实。

如果某条道路没有显著特殊特征，不必强制生成候选区域；**系统性扫描不等于必须覆盖所有道路像素**。

## Step 8：按 Schema 整理并输出

1. 根据 Schema 为最终保留的 ROI 分配唯一标识，并填充规定字段。
   每个区域的 matched_rules 记录实际命中规则的 rule_id 和 rule_name，分别照抄 Rule 的 id/title。多项命中逐项列出，不为凑数量引用无关规则；无具体类型但通用筛选条件成立时可引用 selection_policy 的 id/title。
2. 在 Schema 对应字段中区分**场景事实、潜在定位线索、候选原因和不确定性**；不自行发明字段。
3. 区域的顺序尽量与道路搜索顺序一致，便于后续 BBox 绘制、逐区域裁剪和 Node 5 的并行分析。
4. 如果未发现符合 Rule 的候选区域，返回 {"areas": []}；当前 Schema 不包含原因或状态字段。
5. 输出**仅包含符合 Schema 的 JSON**，不附加过程说明。

## 执行完成前的简要检查清单

- [ ] 已沿可见道路系统搜索，不只盯着显眼建筑。
- [ ] 已考虑道路 Mask 的漏检和误检。
- [ ] 已兼顾潜在有利与潜在退化区域。
- [ ] 已从五类定位视角检查潜在线索，但没有强行一一对应。
- [ ] 已利用屋顶、阴影、遮挡等视觉线索进行合理的定性空间推断。
- [ ] 各候选区域的道路关联、位置和依据一致。
- [ ] 已检查遗漏、重叠和不确定性。
- [ ] 最终 JSON 严格符合 Schema。

---

**实现提示（供 Agent 开发者使用，不作为模型必须输出的内容）**：单次 VLM 调用不能保证大幅面地图的穷尽式扫描或像素级 BBox 精度。对于大幅面 GeoTIFF，可在 Node 1/2 预处理阶段实施有重叠的分块，分别执行本 Skill，再由确定性程序完成块坐标映射、区域去重及 BBox 边界校验；不要让 VLM 自行计算复杂坐标变换。
