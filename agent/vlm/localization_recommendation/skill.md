# Skill：辅助定位方式推荐步骤

按顺序执行，判断依据见 Rule，输出字段见 Schema。

## 第一步：确定评估范围

用边界线确定真实融合区域，并在其中找到道路。线内是评估对象，线外只作环境上下文。

## 第二步：分析环境

在 RGB 上观察，只做定性描述：

1. 区域内和道路周围是否存在树冠、建筑，还是非常空旷。
2. 道路上方的树冠遮挡是连续的还是局部的。
3. 是否有密集或显得高大的建筑结构线索；只描述可见的布局、阴影和屋顶，不估算高度数值。
4. 道路附近是否有墙体、护栏、路缘、建筑立面等可能稳定的三维结构。
5. 环境是否过于单调、平坦或沿路重复。
6. 是否存在隧道、桥下、大量动态目标、季节性植被等可观测性问题。
7. 真实融合区域的不同部分环境是否明显不同。

## 第三步：写下 visual_evidence

把上一步的观察写成可核查的条目，说明位置和地物，例如“区域北侧道路两侧为连续树冠”。不要写结论、数值或传感器性能。

## 第四步：按优先级比较

1. **比较 P0**。看路侧可辨的稳定结构是否足够支持 lio_slam，尤其是转角、不同朝向的结构和沿路变化。再看是否有可辨认的连续路带，能用 wheel_io 短时通过。看到隧道口或开阔广场时，仍要分别检查几何结构和路带是否连续。
2. **检查 P1**。只有两种 P0 对该路段都不适用时，再检查路线沿途是否持续开阔。定位树冠、靠近道路的建筑、桥面等潜在遮挡或反射来源。卫星图上的局部开口不能证明 GPS 沿路可用。
3. **记录不确定性**。道路跨越不同环境，或看不到隧道内部、无法确认路面和结构时，说明缺项。没有一项有充分依据时按 Rule 给出暂定项，并要求复查。

## 第五步：完成结论

- 按 Rule 填写 `assessment` 的四项，用刚才记录的 `visual_evidence` 支撑每项结论。看不清就填 `uncertain`。
- 填写 `recommended_method`。
- `reason` 依据 `visual_evidence` 说明为什么选它，以及为什么优先于另外两种方式；直接描述环境，不要提及 Rule、Skill、字段名或“优先级”。
- `limitations` 写本区域特有的风险和待验证条件。
- 按 Rule 的 `status` 填写 `recommendation_status`，按 `review_required` 的条件填写 `review_required`。
