# Skill：辅助定位方式推荐步骤

按顺序执行，判断依据见 Rule，输出字段见 Schema。

## 第一步：确定评估范围

用边界线确定真实融合区域，并在其中找到道路。线内是评估对象，线外只作环境上下文。

## 第二步：记录道路与结构密度证据

沿同一路带观察前、中、后段，先判断沿路三维结构是**密集**还是**稀疏/单一重复**，并记录路带接续及两侧地物的位置、朝向和变化，写入 `visual_evidence`。

- 判断结构是否密集：看沿路两侧是否有成片树木或连续树带、灌木树篱、建筑与棚屋、院墙、围栏、停放车辆、坡坎或道路弯折。只要沿路存在密集树木植被或构筑物，即属于结构密集——不必有连续临路建筑立面，也不必在树冠遮挡下逐一数清树干。
- 判断结构是否稀疏或重复：仅当沿路为大片开阔农田、空旷广场、草地，或仅有长直平行边界且缺乏沿路三维变化时，才属于结构稀疏或单一重复。
- 岸坡或切坡看坡缘、裸土界面和道路的相对位置，关注坡缘转折。隧道内部有断面或壁龛线索时才描述相应几何。
- 检查同一路带的路面和接续。结合路面边缘和暗带两端的走向判断道路接续，关键暗带可能是沟渠或非道路时保留不确定。

## 第三步：按顺序推荐

1. **structure_density 与 lio_slam**。先判定结构疏密。只要属于结构密集区域（如连续树带、林荫道、住宅区、建筑与植被交错区），即可用 `lio_slam` 过渡，`structure_density` 填 `dense`、`lidar_inertial_slam` 填 `suitable`；若树冠遮挡地面或部分结构需车端核实，将 `recommendation_status` 设为 `requires_validation`，不要因此改选 `wheel_io`。
2. **wheel_io**。仅当区域属于结构稀疏或几何单一重复（`lio_slam` 不适用），且路带连续、可通行、附着风险可控时，才用 `wheel_io` 短时延续位姿。切勿在结构密集区域因路面连续而误选 `wheel_io`。
3. **GPS**。根据沿路天空开阔程度及连续树冠、近路建筑、桥面等线索填写 GPS 两项。仅在前两项均不适用且满足 GPS 条件时选择 GPS。
4. **不确定性**。关键几何或道路接续的证据不足时，写明缺项。没有任何一项有充分依据时按 Rule 给出暂定项，并标记需在线验证。

## 第四步：完成结论

- 按 Rule 填写 `assessment` 的五项（先填 `structure_density`，再填两种里程方式与 GPS 两项），用刚才记录的 `visual_evidence` 支撑每项结论。
- 填写 `recommended_method`。
- `reason` 依据 `visual_evidence` 说明为什么选它，以及为什么优先于另外两种方式；直接描述环境，不要提及 Rule、Skill、字段名或“优先级”。
- `limitations` 写本区域特有的风险和待验证条件。
- 按 Rule 的 `status` 填写 `recommendation_status`。
